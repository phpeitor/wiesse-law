## 🚀 Inicio rápido

1. Clona el repositorio:
```bash
git clone https://github.com/phpeitor/wiesse-law.git
cd wiesse-law
```

2. Abre el proyecto en el entorno que prefieras para ejecutar una landing estática:
```bash
# Ejemplo general: abrir index.html directamente o servir la carpeta desde tu entorno local
index.html
```

## 📁 Estructura del proyecto

```text
wiesse-law/
├── index.html              # Vista principal del sitio
├── css/                    # Estilos, dependencias y assets visuales
├── js/                     # Scripts y comportamiento del frontend
├── img/                    # Recursos gráficos del proyecto
├── fonts/                  # Fuentes locales
├── webfonts/               # Fuentes web adicionales
├── README.md               # Documentación del proyecto
├── .ia-context/            # Contexto operativo para agentes y asistencia IA
└── .git/                   # Metadatos del repositorio
```

## 🧩 Visión general

Este repositorio reúne una landing institucional para un estudio jurídico, construida como una solución estática y orientada a presentar la identidad, la propuesta de valor y la información de contacto de la firma con claridad, autoridad y buen rendimiento visual.

La estructura está pensada para ser simple, directa y fácil de mantener, sin introducir complejidad innecesaria en el ciclo de desarrollo ni depender de un stack específico para su operación básica.

## 🛠️ Enfoque técnico

- HTML5 semántico
- CSS modular y reutilizable
- JavaScript ligero y orientado al comportamiento del frontend
- Recursos locales para mejor control de presentación y rendimiento
- Arquitectura estática, mantenible y adaptable a distintos entornos

## 🔍 Convenciones del proyecto

- Se prioriza la integridad visual y la claridad del contenido institucional.
- Las rutas relativas deben mantenerse válidas desde la raíz del proyecto.
- Los cambios de estilo se gestionan dentro de `css/` y los de comportamiento dentro de `js/`.
- El contenido principal y la estructura general se mantienen en `index.html`.
- El directorio `.ia-context/` registra el contexto operativo para agentes y asistentes de IA.

## ✅ Recomendaciones de mantenimiento

- Mantener una estructura limpia y escalable al momento de editar assets o estilos.
- Revisar el uso de rutas locales antes de incorporar recursos externos.
- Preservar accesibilidad, legibilidad y consistencia visual en cada ajuste.
- Evitar introducir complejidad de arquitectura si el proyecto sigue funcionando como landing estática.

## 🧠 Nota final

El proyecto está orientado a un desarrollo profesional, mantenible y visualmente sólido, con foco en la experiencia institucional del cliente. Su objetivo no es imponer un entorno particular, sino ofrecer una base limpia y adaptable para trabajar con el stack y las herramientas preferidas por quien lo mantenga.

*El contexto operativo del proyecto está documentado en [.ia-context/AGENTS_ROLES.md](.ia-context/AGENTS_ROLES.md) y [.ia-context/FRONTEND_RULES.md](.ia-context/FRONTEND_RULES.md).*
